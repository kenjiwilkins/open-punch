# 07. テスト戦略

## なぜテストを重視するか

**テストの網羅性は、依存を安全に上げ続けるための命綱**として位置づける。`/update-library` の後にテストが緑なら自信を持ってマージできる。これがこのプロジェクトのテスト戦略の芯。

## 方針

- **Unit テスト**と **UI（コンポーネント）テスト**で担保する。
- **E2E は当面やらない**（合意済み）。将来必要になったら再検討。
- テストは CI で毎 PR 実行し、**失敗・カバレッジ低下はマージをブロック**する。

## テストの層

### 1. Unit テスト（Vitest） — `packages/core`, `packages/graphql`
ドメインロジックとデータアクセスの正しさを担保する。ここが最重要。

対象:
- **状態算出ロジック**: 打刻列 → `WorkerStatus`（未出勤/勤務中/退勤済）の畳み込み。複数回の出勤/退勤ペアのエッジケース含む。
- **業務日（businessDate）計算**: JST 基準、日跨ぎの扱い。
- **シングルテーブルのキー組み立て**: `WORKER#<id>` / `PUNCH#<ts>` / GSI キーなどの Repository 関数。
- **打刻書き込み**: サーバー時刻が採用されること（クライアント指定時刻が無視されること）。
- **補正フロー**: 元イベントを書き換えず PunchAudit が append され、両者が **1トランザクション**で書かれること。
- **GraphQL リゾルバの認可**: apiKey モードで cognito 専用オペレーションが拒否されること／その逆。

DynamoDB は **aws-sdk-client-mock** でモックし、実 AWS なしで回す。

### 2. UI テスト（Vitest + @testing-library/react） — `apps/kiosk`, `apps/admin`
ユーザーの主要操作をコンポーネント単位で検証する。GraphQL クライアントは **msw**（またはモック関数）で差し替える。

対象:
- **kiosk**: 名前一覧の表示（有効なアルバイトのみ、かな順）／状態に応じた打刻ボタンの出し分け（未出勤→「出勤」、勤務中→「退勤」）／打刻後に完了表示 → 一覧へ戻る。
- **admin**: 当日打刻一覧のレンダリング／補正フォームの入力・送信／未認証時のガード表示。

## 絶対に外さないテスト（回帰チェックリスト）

セキュリティ・データ整合に直結するので、以下は**常に緑を維持**する:

1. 🔑 apiKey で叩けるのは `workers` / `workerStatus` / `punch` の3つだけ。他の cognito 専用オペレーションは拒否される。
2. `punch` はサーバー時刻を採用し、クライアントが送った時刻は使わない。
3. 補正・手動打刻は必ず PunchAudit を残し、元イベントとトランザクションで原子的に書かれる。
4. `active=false` のアルバイトはキオスク一覧に出ない（GSI1 スパースの検証）。
5. 状態算出: 出勤→退勤→再出勤（中抜け）で正しく `WORKING` に戻る。
6. 入力検証（zod）: 不正な `type` や欠損フィールドが拒否される。

## カバレッジ目標

| 対象 | 目標 |
| --- | --- |
| `packages/core` ドメインロジック | 90%+（状態算出・キー組み立ては 100% を目指す） |
| GraphQL リゾルバの認可分岐 | 100%（全 authz 分岐を通す） |
| UI 主要操作パス | 打刻フロー・補正フローを網羅 |

> カバレッジ率は「安心して依存を上げられる範囲を可視化する指標」。数字を満たすこと自体が目的ではなく、上のチェックリストが守られていることが本質。

## ツール

| 用途 | ライブラリ |
| --- | --- |
| テストランナー | vitest |
| React コンポーネント | @testing-library/react, @testing-library/user-event |
| DOM 環境 | happy-dom（または jsdom） |
| DynamoDB モック | aws-sdk-client-mock |
| GraphQL/HTTP モック | msw |
| カバレッジ | @vitest/coverage-v8 |

## CI での実行（M0 で整備）

```bash
pnpm -r typecheck     # 型
pnpm -r test          # unit + UI
pnpm -r test --coverage
```

- 毎 PR で実行。失敗・カバレッジ低下でマージ不可。
- `/update-library` 実行後は必ずこのスイートを通してから確定する（[.claude/commands/](../.claude/commands)）。

## 運用方針（確定）

- **CI 基盤は GitHub Actions**。PR ごとに typecheck + unit + UI + coverage を実行。
- **カバレッジしきい値は段階導入**: 最初は警告のみ（数値を可視化）、テストが揃ってきたら `vitest --coverage.thresholds` で強制に上げてマージブロックにする。
- 依存更新（`/update-library`）後は必ずこのスイートを緑にしてから確定する。
