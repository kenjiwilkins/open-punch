# 01. プロダクト概要

## 何を作るか

店舗/オフィスに常設したタブレット（iPad 想定）で動く**タイムカードアプリ**。出勤してきたアルバイトが、置いてある端末で自分の名前をタップして打刻する。社員は別アプリ（管理画面）で勤怠を管理する。

## アクター

### アルバイト（Worker）
- 端末の前に立ち、一覧から自分の名前を選んで打刻するだけ。
- **アカウント登録・ログインはしない**。DynamoDB 上のレコードとしてのみ存在する。
- セッションを持たない。「今このアプリを操作しているのが本人か」は保証しない（キオスク前提）。

### 社員（Employee）
- 管理画面にログインして使う。
- **Cognito ユーザー**として認証され、認証済みの社員だけが社員向け GraphQL データにアクセスできる。
- アルバイトの追加/編集、打刻の閲覧、打刻の補正、勤怠集計を行う。

## 利用シナリオ

```
[出勤時]  アルバイトが kiosk 端末の前に立つ
          → 名前一覧から自分をタップ
          → 現在の状態に応じたボタン（出勤/休憩/退勤）をタップ
          → 「打刻しました」表示 → 数秒で名前一覧に自動で戻る

[管理時]  社員が admin にログイン
          → 今日の打刻一覧を確認
          → 打刻漏れ/誤打刻を補正
          → 期間を指定して集計・エクスポート
```

## 設計上の重要な前提

1. **キオスク端末は物理的に店舗内にある**。第一の防御は物理的なアクセス制御。ただし GraphQL エンドポイントはネットワーク的には公開されるため、API キー + 将来的なデバイス制限で保護する（[02-architecture.md](./02-architecture.md) 参照）。
2. **時刻の真実源はサーバー**。打刻時刻はクライアントの時計ではなく、Lambda 側のサーバー時刻を採用する。端末の時計ずれ・改ざんを排除するため。
3. **タイムゾーンは JST（Asia/Tokyo）固定**。**単一店舗確定**なのでタイムゾーン分岐は考えない。
4. **打刻はイベントとして記録**する。1日に複数回の出勤/退勤（中抜けなど）にも自然に対応できる。**休憩は打刻種別を持たず、「一旦退勤 → 戻ったら出勤」で表現する**（合意済み）。

## スコープ外（現時点）

- 給与計算・給与システム連携
- シフト作成/シフト管理
- 位置情報（GPS）打刻
- アルバイト本人のスマホからの打刻

> 🟡 上記のうち「シフト管理」は将来やりたいか？ データモデルに影響するので早めに方向性を握りたい。
